# Completing and extending the 100-case corpus

All 100 scenarios have undergone ASD investigation. There are 99 prediction-equipped portfolios and one scientific abstention with a source-adequacy evaluator. Continue with improved or distinct task versions; there are no unattempted scenarios in this corpus revision. All present outcomes are exposed.

## Scientific lessons

1. Audit the measured endpoint before proposing a law. The graph archive has a constant target, and the imaging subset has no defensible diagnostic truth. A perfect score on the former or an invented target on the latter would misrepresent discovery.
2. Separate released-product prediction from the underlying process. Spectral reconstructions, normalized calcium traces, detector summaries and conditioned survey variables inherit author processing. Native-prefix checks establish only their stated finite scope.
3. Treat calibration as a paid information resource. Specify exactly which pilot, control, early-time or same-sample measurements may be used, their units, and whether they exist at prediction time. Export them explicitly. Offline reference labels cannot silently become online predictors.
4. Mask information when it becomes available, not merely by its table column. Case 88's unannounced feedback type and case 2's future-bin timestamp required corrections. Retain the earlier implementation and show whether frozen predictions change.
5. Compare against robust and flexible alternatives under identical access. Classical or simple rules sometimes win. A post-confirmation challenger may diagnose a weakness, but cannot replace the development-selected reference in the original confirmation claim.
6. Report competing error objectives. Case 31 improves log error but worsens absolute seconds; case 49's MAE advantage does not establish uniformly better tail error. Source weights define an estimand; they are not an automatic national-population estimate.
7. Distinguish an executable predictor, an exact certificate and a physical explanation. Case 98 supplies an exact combinatorial check and a tie-regime counterexample. Accuracy of a floating-point solver is a separate statement.
8. Count substantive hypotheses and counterexamples, not failed implementations or seed changes. The 45-case campaign contains 267 substantive investigations; case 62's invalid technical attempt is retained but excluded from that count.
9. Preserve negative evidence. Cases 7, 9, 50, 75, 80, 81 and 97 limit stronger claims. A justified abstention is a valid result and must not be converted into a fabricated score.
10. Keep human and machine contracts synchronized. Reader PDFs, task JSON, input units, calibration exports, protocol versions and review packets must describe the same information budget. Exact source and prediction bytes remain unchanged by prose improvements.

## Reusable workflow

Start from the catalog, current task contract and source audit. Record exposure before opening any outcomes. Freeze targets, source hashes, groups, inputs, primary metrics, baselines and selection rules before fitting. Use whole-group development validation, including training membership and transformations. Perform at least five genuinely different investigations, preserve failures, and stop continuation using development evidence only. Freeze before confirmation. If all data are already exposed, call the next analysis retrospective unless new independent evidence is obtained.

Use separate computational and scientific-critical reviews. Recompute numerical results, inspect source semantics, test native counterfactual prefixes where applicable, and challenge mechanism and transfer claims independently. Review disagreement remains visible; it is not resolved by an aggregate discovery score. Agents do not substitute for independent experiments or human scientific adjudication.

Registered tasks accept alternative equations under the same measurement and calibration contract. Different endpoints require `propose-task`, evidence anchors, controls and independent review before contract registration. Prediction-file scoring executes no submitted code; optional trusted replay is explicit local execution. No hosted untrusted-code service is supplied.

## Integrity and publication

Standalone packages must reject missing, empty, unsafe or corrupted manifests. Native preparation must verify immutable assets before importing an adapter and must not fit a model or read historical prepared targets as inputs. Declare calibration columns explicitly. Reproduce saved predictions and physical-unit/group metrics; test malformed submissions, mismatched identities and nonfinite arithmetic.

Keep `final_results/` concise, with an English PDF and editable Markdown, equations, compact evidence and runnable references. Keep scientific reasoning and failures in `research_history/`; put redundant operational outputs outside the release allowlist. Update instructions and evidence records, not private machine memory. All publication remains a separate user-authorized action. Optional cycling supplemental data remain excluded until data-specific redistribution rights are resolved.
