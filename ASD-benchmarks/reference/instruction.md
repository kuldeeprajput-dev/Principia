# Extending Principia-100

Respond and write benchmark artifacts in English. Use this layer's registry and schemas as the current contract; preserve earlier research trees and raw sources. Keep publication separate from local preparation.

1. Start from an unused registry case. Audit the native source, units, quality flags, calibration, preprocessing, published analyses and independent experimental units. Confirm rights and hash every consumed asset. A source-aware dataset does not provide unknown truths automatically.
2. Before fitting, freeze a task: endpoint, units, prediction time, permitted history/calibration, linked groups, chronological constraints, exclusions, baseline information access, primary metric, aggregation, uncertainty and selection/stopping procedure. A changed target or information budget requires a distinct task ID/version.
3. Write a deterministic raw adapter using only native corpus assets and declared metadata. Emit predictors, observations, source anchors, eligibility, calibration and split/group metadata. Freeze any learned preprocessing with training scope. Supplemental data need separate task IDs, native manifests and explicit rights; they cannot silently enter the core.
4. Conduct substantive hypothesis-driven attempts with development-only selection. Preserve unfavorable hypotheses and failed mechanisms. Do not count seed changes or equivalent parameterizations as new findings. Record exact equations, coefficients, units, counterexamples, identifiability and physical limits.
5. Freeze candidates and stopping decisions before confirmation. Once outcomes are opened, mark them exposed. Later improvement is retrospective until genuinely fresh data are obtained. Do not rebuild the same holdout's freshness by renaming it.
6. Export a standalone reference using frozen numerical states, no historical imports, no networking and no hidden prepared-table lookup. Demonstrate raw preparation, prediction replay and independently recomputed metrics. Keep OOF and deployment states distinct.
7. Build one concise final_results package: FINDINGS.md/PDF, finding/model/task index, explicit equations and coefficients, run.py, compact evidence, task/evaluator instructions and limitations. Put valuable reasoning and failures in research_history, disposable operational copies outside the release allowlist. Do not delete source evidence during cleanup.
8. Use the shared evaluator. Test arbitrary valid alternative equations, mismatched versions/units/budgets, all-abstention, missing targets, signed/log targets, weighting, tied intervals, complete event failure, duplicate identities, malformed/nonfinite inputs and corrupted assets. Add task-specific timing, linked-group, calibration and physical tests. Never equate dependent rows with independent replicates.
9. Obtain separate computational and scientific-critical reviews, bound to exact claim/evidence hashes. Preserve disagreements. Assess mechanism and novelty separately from prediction; neither an LLM nor a small numerical improvement is independent experimental replication. Allow negative findings and justified abstentions. Do not manufacture a gold discovery or composite discovery score.
10. Update registry.json, generate catalogs/task cards, verify manifests and source preservation, register per-asset lineage/rights, and assemble an explicit local release allowlist. Exactly label pending cases. Only the user can authorize a later publication.

The task identity is scenario + task + protocol + cohort + evaluator version. Findings, models and tasks have separate stable IDs. All current 100 portfolios are exposed to future users. A future submission can establish a valid alternative discovery; matching these reference equations is never required.
